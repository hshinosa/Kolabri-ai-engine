## 1. Runtime Safety Contract

- [x] 1.1 Inventory existing safety, guardrail, and error-classification paths across request handling and provider execution. — see `design.md` § A. Mapped: `app/middleware/auth.py` (API-key), `app/middleware/request_size_limit.py` (10 MB cap), `slowapi` rate limiter (`main.py:135`), `app/core/guardrails.py` (`Guardrails.check_input` `:233`, `check_output` `:464`) composing `InjectionDetector` / `ToxicityScorer` / `PIIDetector`, `app/services/circuit_breaker.py` LLM wrapper, `app/services/llm.py:20-25` retry/timeout constants, and three FastAPI exception handlers in `main.py:170-220`. Three gaps identified: no distinct guarded outcome, degraded vs terminal collapse into 500, no `request_id` (zero matches in `app/`).
- [x] 1.2 Define the explicit guarded, degraded, and terminal outcome contract for AI-engine responses. — see `design.md` § B. Three-state taxonomy: `guarded` (200/403, body carries `outcome` + `reason` + `message`), `degraded` (503, body adds `retry_after`), `terminal` (500, extends today's `INTERNAL_SERVER_ERROR` shape with `outcome` + `request_id`). `detail` field preserved for backward compatibility with current Core API consumers.
- [x] 1.3 Map the required runtime safety checkpoints across ingestion, retrieval, generation, and intervention flows. — see `design.md` § C. Per-flow checkpoints: ingestion (size + MIME validation → guarded on rejection), retrieval (grounding floor → guarded when not met instead of silent low-confidence answer), generation (circuit breaker / retry exhaustion → degraded), intervention (decision auditability via diagnostics path).

Switch overall `degraded` overall status to HTTP `503` (currently silently `200` for HTTP probes).
